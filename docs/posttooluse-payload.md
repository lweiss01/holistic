# PostToolUse Hook Payload Audit

> **Status:** FILLED from a real capture on 2026-05-30. Every field below reflects payloads actually delivered on this machine via a Node capture hook, not docs or memory. Verdict tables have no UNKNOWN rows. This unblocks the Andon collector work (see `SPEC-decisions-capture-andon.md` Section 3 and `SPEC-andon-ingestion-contract-addendum.md`).

## 0. Why this exists

Andon's drift engine already consumes semantic events (`agent.scope_expansion_detected`, `agent.retry_pattern_detected`, `file.changed`) but nothing produces them. The producer is a collector that turns raw PostToolUse hook payloads into `AgentEvent` objects. Before writing that collector we needed the actual shape of the payload as delivered on this machine, because every detector depends on specific fields existing (tool name, file path, args, timestamps). This audit records that ground truth and maps it to the target `AgentEvent` shape.

The PostToolUse hook is a Claude Code hook event. The repo previously managed only git hooks and a Claude Code SessionStart hook; PostToolUse was not wired. This audit precedes wiring it.

## 1. Capture method

- Claude Code version: FILL by running `claude --version` (not captured by the hook; record it here for reproducibility)
- OS / platform: Windows 11. Project on `D:` drive, Claude transcript store on `C:` drive.

  No `matcher` key, so the hook matched every tool.
- Capture command / redirection: the Node hook reads the payload off stdin and appends it to `posttooluse-capture.log` at the repo root, tagged with an ISO receipt timestamp and the tool name. It always exits 0.
- Date captured: 2026-05-30
- Number of distinct payloads captured: 17 events across 8 tool categories (Read, Glob, Bash, ToolSearch, AskUserQuestion, Grep, Write, Edit). The redaction applied was masking the Windows username in `transcript_path` to `<user>`; no other edits.

## 4. Field mapping to `AgentEvent`

Target shape (from `packages/andon-core/src`):

```ts
interface AgentEvent {
  id: string;
  sessionId: string;
  runtime: AgentRuntime;
  type: EventType;
  phase: SessionPhase;     // plan | research | execute | test
  source: EventSource;     // "collector" for hook-derived events
  timestamp: string;       // ISO 8601

```

| --- | --- | --- | --- |
| `id` | `tool_use_id` | DERIVED (reuse) | Reuse `tool_use_id` rather than generating. Stable, unique, and gives free dedup if the hook ever double-fires. |
| `sessionId` | `session_id` | DIRECT | Present in every category. The critical question is answered YES. |
| `runtime` | n/a | CONSTANT `"claude-code"` | |

## 6. Gaps and required derivations

1. **No `timestamp` in the payload.** Stamp at hook receipt time in the collector. Accept jitter; for ordering rely on capture sequence plus `tool_use_id`.
2. **No `phase` in the payload, and Holistic state is the wrong source for it.** Supply Andon's `SessionPhase` from the bridge session context, or infer it from the tool mix over a window. Do not map it from Holistic's roadmap `phaseTracker`.
3. **Path normalization is required (the one real engineering task).** `tool_input.file_path` is absolute with backslashes; `tool_response.filenames` are repo-relative with backslashes; `expectedScope` is assumed repo-relative forward-slash. The collector must normalize the touched path before the `startsWith` scope check. See Section 7.
4. **Bash hides file paths inside `command`.** Scope detection on files touched by Bash needs command parsing. Treat as NEEDS-DERIVATION, or accept Bash as a coarse signal and rely on Write/Edit for precise scope tracking.

## 7. Path-shape note (critical for scope detection)

`isPathOutsideScope(path, scope)` in `status-engine.ts` does a `startsWith` check against `holisticContext.expectedScope`. The capture shows three different path forms in play:

- Observed path forms in payload:
  - `tool_input.file_path` (Read/Write/Edit) and `tool_input.path` (Glob/Grep): absolute Windows, backslashes, for example `D:\Projects\active\holistic\AGENTS.md`.
  - `tool_response.filenames` (Glob/Grep): repo-relative, backslashes, for example `packages\andon-core\src\status-engine.ts`.
  - Bash `command` paths: whatever the agent typed; in this capture forward slashes, for example `D:/Projects/active/holistic`.
  - `cwd` is always present and absolute (`D:\Projects\active\holistic`), so it anchors normalization.
- `expectedScope` entry form: assumed repo-relative forward-slash (confirm against `HolisticContext` / `status-engine.ts`).
- Normalization required before comparison: take `tool_input.file_path`, strip the `cwd` prefix to make it repo-relative, replace backslashes with forward slashes, then `startsWith` against `expectedScope`. Equivalently, normalize both sides to absolute forward-slash. Without this, every path reads as uniformly in-scope or out-of-scope, which is the exact silent failure the original note warns about. This is amplified on Windows by the backslash convention and by the project living on `D:` while the transcript store is on `C:`.

## 8. Conclusion

- Overall verdict: FEASIBLE on the current hook shape. Every field the Section 3 detectors need is present. `session_id` rides on all 8 tool categories, so the deep tier and session correlation hold. Full `tool_input` supplies complete args, `tool_input.file_path` supplies the touched path, and `tool_use_id` gives a stable event id and dedup key.
- Blocking gaps: none that block. The one required engineering task is path normalization (Section 7), which is straightforward. `timestamp` and `phase` come from outside the payload by design, not as defects.
- Recommended next step: build the native Claude Code adapter (PostToolUse to `AgentEvent`) per `SPEC-andon-ingestion-contract-addendum.md`, implementing the Section 7 path normalization first because the scope detector depends on it, and reusing `tool_use_id` as `AgentEvent.id`. Capture `permission_mode` into `payload` so a future non-default mode can act as a risk signal, and treat AskUserQuestion as the operator-gate event noted in Section 4.
